# Y15：绝对寻址重构 —— 做了一半，撤回了

> 目标：让层的激活缓冲区也能放在 12 MiB 扩展窗口里。
> 动机很硬：128×128 输入时，tiny-yolov3 的 stem 一层就产出 `128*128*16 = 256 KB`，
> 而 scratch 只有 64 KiB。不改寻址就跑不了有意义的分辨率。
>
> **结果：改动做到一半，出现无法快速定位的故障，已完整撤回。** 这一轮记录证据和
> 下一步该怎么切，免得下次重新走一遍。

---

## 1. 改了什么

层描述符里的 `src_off` / `pad_off` / `out_off` / `wt_off` / `bias_off` / `cfg_off` / `skip_off`
从**相对 scratch 的偏移**改成**绝对地址**：

```c
static void net_wr8(uint32_t addr, uint8_t v) { *(volatile uint8_t *)(uintptr_t)addr = v; }
```

配套改动：`net_conv` 里 6 处 `MT_BUF_BASE + X` 去掉基址；`mt_net.h` 的 `PAD_BUF`/`OUT_BUF`/… 
加基址；四个测试文件（`mt_wide`/`mt_res`/`mt_yolo`/`mt_yolocnn`）的常量同样加基址。

改动本身是机械的：把所有偏移表达式外面套一层 `MT_BUF_BASE +`。

---

## 2. 结果：mt_net 越界，mt_wide 挂死

```
miniTensor YOLO-shaped net (32x32x4 -> 8x8x8 head).
[ERROR] mem.cpp:93 out_of_bound  Address: 0x83430000 is out of bound at pc: 0x80000d9c
```

### 已经查到的

1. **层的地址字段本身是对的**。在 `mt_net_command` 里加了打印：

```
L1 src=80338800 pad=80330000 out=80334000 wt=80337000 bias=80338000 cfg=80338400
```

全部落在合法范围（0x8010_0000–0x80FF_FFFF）内。

2. **故障 PC 在 `net_conv` 内**（`nm -S` 给出 net_conv = 0x800009d8，大小 0x6E4，
   即 0x800009d8–0x800010bc，0x80000d9c 在其中）。

3. **反汇编显示这是 A 行加载**：

```
80000d6c: lw  s11,0(a1)        # tap_wrow[q]
80000d70: lw  a1,0(a2)         # tap_off[q]
80000d74: lw  a0,20(s5)        # L->pad_off
80000d78: li  a2,492           # MT_ROWS(UB_A, 1u) = 236 | 1<<8
80000d7c: add a1,s10,a1
80000d80: slli a1,a1,0x4       # *16
80000d84: add a1,a1,a0         # + pad_off
80000d88: lw  a0,76(sp)
80000d8c: jal mt_push
```

故障地址 `0x83430000` 的低 16 位是 0，形状像**一个基址**而不是一个算出来的偏移；
并且 `0x83430000 - 0x80330000 = 0x03100000`，不像任何合法缓冲区的偏移。

4. `mt_wide` 也失败（无输出挂住），说明不是 `mt_net` 独有的问题。

### 没能确定的

没有定位到具体是哪一条访存。反汇编窗口里 `lw a0,20(s5)` 读的是层描述符，
`s5` 若损坏则故障地址正好是 `s5+20`；但 `s5` 来自 `net_conv(&L1, ...)`，
`L1` 是 `static const`，地址应当是合法的。**这一点没有证实也没有证伪。**

---

## 3. 决定：撤回

保持七个测试全绿，比留下一个半成品更有价值。撤回后重新验证：

```
mt_conv PASSED | mt_net PASSED | mt_detect PASSED | mt_wide PASSED
mt_res PASSED  | mt_yolo PASSED | mt_yolocnn PASSED
```

`mt_net.c` 里留下了注释说明这次尝试和它为什么被撤回。

---

## 4. 教训：这次的做法本身就错了

前面几轮的教训是「一个用例通过 ≠ 功能正确」，所以这一轮我想一次到位。**但这正是问题**：

**把七个测试的寻址约定同时改掉，等于同时拆掉了所有能用来二分的参照物。**
`mt_net` 挂掉时，我没有任何一个「已知正确」的、使用新约定的用例可以对照 ——
而旧的约定又已经全部被改掉了。

正确做法应该是：

1. 先只改 `net_pad`/`net_conv`/`net_pool2` 三个函数和**一个**最小测试（`mt_wide` 最合适，
   它只用一个层、没有池化、没有跳连）；
2. 确认那一个通过；
3. 再逐个迁移其余测试。

这样任何一步失败都能立刻定位到「刚改的那一个」。

---

## 5. 下一步（明确的）

1. 按上面的顺序重做：引擎 + `mt_wide` 先行，其余逐个迁移。
2. 如果需要更快的定位手段：在 `net_conv` 里对每条 `mt_push` 的地址加一次范围断言
   （`addr` 必须落在已知的缓冲区区间内），失败时打印缓冲区名和索引 —— 这比反汇编快得多。
3. 一旦绝对寻址稳定，128×128 的完整骨干就可以跑（激活放扩展窗口，权重放 8 MB blob，
   两者都已就绪）。
