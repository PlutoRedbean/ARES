# 盘古 200Pro+「隐私守门人」：可行性评估与实施计划

> 状态：Draft v0.2（M1/M2 已落地；板上 UART 原型已跑通 —— 见
> [m1-results.md](m1-results.md)、[m2-results.md](m2-results.md)、[board-uart.md](board-uart.md)。
> 实测把 §3.3 的"150 MHz / 150 MB/s"拉回现实：规则层单周期校验链 ≈75 ns，
> 27 MHz 不收敛，当前板上核心 10 MHz（UART 仍是瓶颈）。校验链流水化后才能提频。）
> 日期：2026-11-15（v0.2 同日修订）
> 器件：PG2L200H-6IFBB676（Pangu 200Pro+ / MES2L676-200HP）
> 复用：ARES 单发射流水核（8 级寄存器 / 9 功能单元）+ miniTensor
> 目标：本地离线、先脱敏再出网的分层降级 PII 网关

---

## 0. 结论先行

1. **第一层（FPGA 规则/DFA）完全可行，而且应该做成独立可交付的基础防护**：
   约 12–15k LUT、25 个 DRAM36K、**0 字节 DDR3 流量**，端到端延迟亚微秒，
   与后级模型完全解耦。先把它做完，项目就已经有可演示、可写论文的东西。
2. **第二层有两个不同的瓶颈，别混为一谈**。0.5B 模型 INT4 权重约 250 MB，
   1 GB DDR3（32-bit @1066 Mbps，峰值 4.27 GB/s，实测按 2.5–3 GB/s 估）扫一遍
   的**下限约 90–100 ms**。由此：
   - **编码器（encoder）路**：一次前向覆盖整段（512 token），权重只扫一遍 →
     0.5B 约 **1.3–5 s/段**，0.2B 约 **0.5–2 s/段**，真正做到"秒级"。
   - **自回归解码器（decoder）路**：权重按 token 反复扫 → 单条 **~11 token/s 上限**，
     自由生成 300 token 要 **~27 s**；改成"只输出 BIO/span 标签"的约束解码
     （50–100 个输出 token）可压到 **~5–6 s/段**，但本质上仍是"十秒级"。
   - 结论：**"0.5B 语义层"要落在编码器或约束解码上，才配得上"秒级"这个词**；
     自由生成的 0.5B 聊天模型不适合放在这条链路上。
3. **"分层降级"叙事成立且是最大加分项**：硬件规则层保证"即使模型不行也不会裸奔"，
   模型层失败只损失召回率、不损失可用性；每一级都在输出头与审计日志里显式标注
   当前档位（可解释、可验收）。
4. **工程量**：1 人全职约 **20 周**（M0–M6）；只做第一层 + 演示约 **6 周**。
   最不确定的是 M0 的 DDR3 落地（现有 ARES SoC 只有 BRAM，DDR3 IP 在 `gesture/cam`
   侧、是 AXI4 接口）和 M3 的 INT4 阵列效率。

## 1. 现状盘点（都是仓库里已有的东西）

### 1.1 计算与存储（PDS 实测，见 `gesture/docs/PROGRESS.md` §2.2）

| 资源 | 器件容量 | 已用（视觉基线） | 本项目可用（不用视觉线） |
|---|---|---|---|
| LUT | 120,300 | 62,727（53%） | ≈ 110k（扣掉核与视频外设） |
| FF | 240,600 | 78,293（33%） | ≈ 230k |
| DRAM36K（36 Kb/块，共 1.87 MB） | 415 | 194（47%） | ≈ 330 |
| APM（18×18） | 740 | 261（36%） | ≈ 700 |
| CLMA | 30,075 | 18,369（62%） | — |

ARES 流水核（含 IROM 与 256 KiB DRAM 阵列）单独约：**8.2k LUT / 6.6k FF /
20 APM / 86.5 DRM**；三个 CoreMark 加速器只占 2.8k LUT。
时序参考：视觉线 `clk_pe` Fmax 162 MHz；核 200 MHz 已 PnR 过。
→ **200 MHz 数据通路 + 100 MHz CPU 是合理目标区间**。

### 1.2 ARES 流水核（控制面）

- 单发射、8 级寄存器 / 9 功能单元（IFU/IDU/ISU/EX1/EX2/EX3/EX4/LSU/WBU），
  CoreMark 13.38 CM/MHz（Verilator，单核全加速）；
- I$ 4 KiB 4 路、D$ 8 KiB 2 路写直达；UART TX 已上板（C24, 115200 8N1）；
- **UART RX 引脚当前没有定义**（`pipeline_board.fdc` 里 tie 成 1）——
  做文本入口必须先补 RX 引脚，这是 M0 的第一个具体动作。

### 1.3 miniTensor（数据面模板）

| 项 | 当前实现（`ARES/docs/microarch/miniTensor.md`） |
|---|---|
| 接口 | CV-X-IF（issue/register/commit/result）+ 128-bit uncached R/W |
| 片上缓冲 | UB 256 行 × 128 bit（4 KiB）、VRF 32 × 128 bit |
| 向量 | 16-lane INT8 VPU |
| 矩阵 | **4×4 INT8 脉动阵列，INT32 累加，固定 10 拍窗口** |
| 流水 | 单命令顺序执行，**无流水、无双缓冲、单 outstanding DMA** |
| 已验证 | tiny-yolov3 INT8（21 stage）逐字节对齐，RT-Thread Nano 上跑通 |

→ 它是"能跑通 INT8 CNN 的最小正确实现"，但对 0.5B Transformer 来说
**阵列太小（16 MAC/cycle）、没有片上流水、没有 INT4 路径**。本项目的核心硬件工作
就是把它扩成 `16×16 W4A8` 双缓冲版本（见 §4）。

### 1.4 板卡（公开规格，MES2L676-200HP）

- DDR3 ×2，共 8 Gbit（1 GB），32-bit，最高 1066 Mbps → **4.27 GB/s 峰值**；
- 1× 10/100/1000M 以太网；HDMI in/out；USB-UART；PCIe Gen2 x4；8 路 HSST；2× SFP；
- 现有仓库只有 HDMI/DDR3/摄像头/UART 的引脚约束，**网口/PCIe 都没有现成约束**。

## 2. 系统架构

```
                 ┌─────────────────────────── 盘古 200Pro+ ───────────────────────────┐
  源文本流  ──►  │  L0 分帧/队列          L1 规则引擎 (always-on)                      │
  (UART 3Mbaud   │  ────────────►  ┌─────────────────────────────┐                    │
   或千兆网口)   │   ring buffer    │ 数字串检测 → 校验 → 命中 span │                    │
                 │                  └──────────┬──────────────────┘                    │
                 │                             │ spans(规则号/类型/位置/置信=1.0)       │
                 │                  ┌──────────▼──────────────────┐                    │
                 │                  │  L2 调度器（RV32 + 策略 FSM）│◄── 审计环/统计      │
                 │                  └──────────┬──────────────────┘                    │
                 │            需要语义判定?     │ 否 → 直接放行                        │
                 │                  ┌──────────▼──────────────────┐                    │
                 │                  │ L2a 语义引擎（INT4 encoder） │  DDR3: 权重 250 MB │
                 │                  │ 16×16 W4A8 + tokenizer(BPE)  │  双缓冲流式         │
                 │                  └──────────┬──────────────────┘                    │
                 │                             │ BIO/span + 置信度                    │
                 │                  ┌──────────▼──────────────────┐                    │
                 │                  │ L3 融合/替换/审计            │──► 输出（脱敏文本   │
                 │                  │ 标签化 [ID_1] 或掩码 尾4位    │    + 档位头 + 审计） │
                 └──────────────────────────────┬──────────────────────────────────────┘
                                                ▼
                                    目的端（本地应用 / 云端）
```

**档位（降级语义）**

| 档位 | 内容 | 触发条件 | 延迟预算 | 保证 |
|---|---|---|---|---|
| T0 | 直通（fail-open） | 仅运维显式开启 | 0 | 无（必须记录） |
| T1 | 仅 L1 规则 | 默认；模型不可用/队列堵/超温/超功耗 | < 10 µs | 格式化 PII 必拦 |
| T2 | L1 + L2a 编码器 | 正常 | 1–5 s/段 | 语义 PII 尽力 |
| T3 | L1 + L2b 复核（可选解码器/更大模型） | 高敏文档、人工抽检 | 十秒级 | 最高召回 |

**降级判据**（写进 RTL/固件，可配置）：L2 队列深度 > N、p99 延迟 > 预算、
DDR3 带宽占用 > 80%、温度/功耗超限、模型自检失败。每次切换都写审计事件
（reason/时间/档位），并给输出加 `X-Privacy-Mode` 头。

**可解释性**：每个被替换的 span 都带 `{type, start, len, source: rule_id|model+conf,
action: mask|token|drop}`，默认随输出回传一份 JSON 审计摘要；可开关。

## 3. 第一层：规则/DFA 引擎（先做，独立可交付）

### 3.1 检测范围（第一版）

| 类型 | 规则 | 校验 |
|---|---|---|
| 身份证（18 位 / 15 位） | `[1-9]\d{5}(18|19|20)\d{2}(0[1-9]|1[0-2])(0[1-9]|[12]\d|3[01])\d{3}[\dXx]` | ISO 7064 MOD 11-2 + 出生日期合法性 |
| 手机号 | `1[3-9]\d{9}`（可加分隔符容错 `-`/空格） | 号段表 |
| 银行卡 | 13–19 位数字串 | Luhn + BIN 段（可配） |
| 邮箱 / IPv4 | 常规正则 | 域名后缀表 |
| 车牌 / 统一社会信用代码 | 可选 | 字符集 + 校验位 |

### 3.2 微架构

- **数字游程扫描器**：对字符流做"连续数字长度"计数 + 分隔符判定，天然支持
  `138 0013 8000` 这类带空格写法；
- **并行校验单元**：MOD 11-2（身份证）用 2 拍流水；Luhn 用 1 拍；
  日期用 12 项 ROM；三者共享一个 18 字节窗口；
- **关键词 AC 自动机**（可选，为 L2 提供提示，如"身份证/银行卡/手机"上下文）：
  状态 × 字符类表放 BRAM，约 8–16 个 DRAM36K；
- **hold-and-forward**：命中后需要回退覆盖已发出的前缀（例如身份证要看到第 18 位
  才能判定），因此出口保留 32 字符窗口 + 命中 span 队列，未命中的字符延迟 ≤ 32 字符；
- **DDR3 流量 = 0**：全部在片上 BRAM/FIFO，权重/表在 ROM。

### 3.3 资源与延迟预算（目标，M1 由 PDS 实测）

| 子块 | LUT | DRAM36K | APM |
|---|---|---|---|
| 数字游程 + 分隔符 | 2k | 0 | 0 |
| 校验单元（ID/Luhn/日期） | 2k | 1 | 0 |
| 关键词 AC | 2k | 8–16 | 0 |
| span FIFO + 替换器 + 审计 | 3k | 4 | 0 |
| UART 2×3 Mbaud / 分帧 | 1k | 0 | 0 |
| **合计** | **≈ 12–15k（10–12%）** | **≈ 25（6%）** | **0–8** |

吞吐：1 字符/拍 @150 MHz = 150 MB/s（1 Gbps 线速 = 125 MB/s，够用）；
延迟：窗口回退 32 字符 + 流水 ≈ **0.3 µs 量级**；命中判定正确率以 PC 端
Python 金标 1 万条用例逐条比对（目标 100%，因为规则是确定性的）。

## 4. 第二层：INT4 语义引擎（真正的工程重心）

### 4.1 为什么必须改"编码器优先"

| 路线 | 权重扫描次数 | 单段(512 token)延迟 | 备注 |
|---|---|---|---|
| 0.5B **encoder**（token 分类头） | 每段 1 次（250 MB） | 计算受限：**1.3 s（P2）/ 5 s（P1）** | 全序列并行，无 KV 增长 |
| 0.5B **decoder**，约束输出 50–100 token | 每 token 1 次（250 MB） | **≈ 5–10 s** | 需要 KV cache（8 并发 ≈ 200 MB） |
| 0.5B **decoder**，自由生成 300 token | 同上 | **≈ 27 s** | 单流上限 ≈ 11 token/s |

- 编码器是**算力受限**：一段 512 token 只扫一遍权重（250 MB → 带宽仅需
  0.05–0.2 GB/s，DDR3 根本不紧张），时间全花在 MAC 上（256 GMAC）。
- 解码器是**带宽受限**：**250 MB / 2.7 GB/s ≈ 93 ms 一个 token**，谁也绕不过。
- 所以"0.5B 秒级"只能靠"一次扫描覆盖整段"，也就是编码器（或 prefill 批处理 +
  约束解码），自由生成的 0.5B 聊天模型天生就是十秒级。

### 4.2 三档阵列规模（可配置，先做 P1）

| 配置 | MAC/cycle | APM | @200 MHz | 0.2B encoder 512tok | 0.5B encoder 512tok | 权重带宽需求 |
|---|---|---|---|---|---|---|
| P0 8×8 | 64 | 32 | 13 GMAC/s | ~8 s | ~20 s | 2.7 GB/s 打不满 |
| **P1 16×16（推荐）** | **256** | **128** | **51 GMAC/s** | **~2 s** | **~5 s** | ≈ 0.05 GB/s |
| P2 32×32 | 1024 | 512 | 205 GMAC/s | ~0.5 s | ~1.3 s | ≈ 0.2 GB/s |

> 说明：编码器单段就把权重扫完了，所以 P2 并不缺带宽，它缺的是"更短的单段延迟"
> ——收益只来自算力（5 s → 1.3 s），代价是 4 倍 APM。P0 则反过来：省 APM 但延迟
> 20 s，已经不算"秒级"。**P1 是单段延迟与资源的最优折中**；P2 留给"要 1 s 级"的场合。

### 4.3 数据通路改造（相对 miniTensor）

1. **阵列**：4×4 INT8 → 16×16 **W4A8**（权重 4-bit 分组量化，激活 8-bit，
   INT32 累加；group size 64，per-channel scale 在片上 ROM）；
2. **双缓冲**：A/B 权重 tile 各 16 KB，`vpu_dma` 从"单 outstanding"升级为
   描述符化 burst（AXI 读 32 字节/拍），与计算重叠；
3. **Transformer 算子单元**：RMSNorm（1/√ 用 LUT + 牛顿迭代）、RoPE（正弦表 ROM）、
   SiLU（LUT）、softmax（max + exp LUT + 倒数）、mask（因果/填充）；
4. **注意力**：flash-attention 式分块，`512×64` tile 常驻 BRAM，不落 DDR3；
5. **激活常驻**：`512 token × 768 hidden × 1 B = 384 KiB`（≈ 86 DRAM36K），
   单层进出 DDR3 只在层间 spill 时发生（可关掉，靠 400 KB 预算吃下）；
6. **tokenizer**：BPE 词表（~150k）放 DDR3（≈1 MB），RV32 二分查找 + DDR3 行读，
   实测目标 < 2 µs/token（512 token ≈ 1 ms，可忽略）；
7. **量化/反量化**：INT4 → INT8 反量化在 PE 入口做（移位+乘 scale），
   与权重加载流水。

### 4.4 0.5B 编码器的资源/带宽预算（P1）

| 项 | 用量 | 占比 |
|---|---|---|
| 16×16 W4A8 阵列 + 反量化 | ~25k LUT / 128 APM | 21% / 17% |
| 归一化/RoPE/SiLU/softmax | ~6k LUT / 16 APM | 5% / 2% |
| 激活缓冲（384 KB）+ tile 双缓冲 | ~100 DRAM36K | 24% |
| 控制器/DMA/描述符 | ~8k LUT / 10 DRAM | 7% |
| RV32 SoC（含 IROM/DRAM）+ L1 | ~20k LUT / 90 DRAM / 20 APM | 17% / 22% / 3% |
| **合计** | **~59k LUT / ~200 DRAM / ~164 APM** | **49% / 48% / 22%** |

→ 资源上**放得下**，还留出 40% 余量给视频/网口/调试。
DDR3 预算：权重 250 MB + 激活 spill 8 MB + tokenizer/审计 32 MB + KV（解码器档才要）
≈ 300 MB / 1 GB，双缓冲与审计环都不紧张。

## 6. 风险登记

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | ARES SoC 无 DDR3 通路（只有 256 KiB BRAM），DDR3 IP 是 AXI4 且未与核集成 | 阻塞 M2–M4 | M0 先做桥（AXI4→128-bit uncached 握手），复用 `ddr3_test` 例程 |
| R2 | UART RX 引脚未定义（现有 profile 只 tie 1） | 阻塞文本入口 | 查 676 板原理图补约束；备选千兆网口（+4–6 周） |
| R3 | APM INT4 打包效率不确定（2×int8 / 4×int4 是否成立） | 算力腰斩 | M3 综合实测；退路：P0 8×8 + 更小模型（0.2B），仍能 2–8 s |
| R4 | INT4 精度不足（人名/地址召回掉点） | 语义层失效 | 分组量化 + per-channel scale；W8A8 回退（算力减半、延迟 ×2） |
| R5 | 200 MHz 下 1024 MAC 阵列时序不收敛 | 降频 | 目标 150–180 MHz；或 P1 的 256 MAC（更易收敛） |
| R6 | 0.5B 用错形态（decoder 自由生成）导致"秒级"承诺落空 | 指标不达标 | **决策点 A**：默认 encoder；decoder 只做 M5 的复核档 |
| R7 | "透明网关"物理形态（旁路/在线）需要网口与协议栈 | 演示形态不完整 | 第一版做"主机前置网关"（UART），网口形态列 M6 可选 |
| R8 | 权重 250 MB 的存储/加载链路（flash→DDR3） | 启动慢 | 上电从 SD/flash 预载；调试期 PC 经 UART 灌入（≈ 5 min，仅开发用） |

## 7. 需要拍板的三个决策点

- **A. L2 形态**：① 0.5B 编码器（推荐，1.3–5 s）；② 0.5B 编码器 + 0.5B 解码器复核
  （两档，召回最高）；③ 0.5B 解码器约束解码（~5–6 s，可顺手做"改写/告警"）。
- **B. 第一版数据面**：① USB-UART 3 Mbaud（推荐，6 周可演示）；② 千兆网口
  （更像网关，但要 PHY/RGMII + 精简协议栈，+4–6 周）；③ 先 UART 后网口。
- **C. 权重来源**：① 调试期 PC 灌入 + 运行期 DDR3 常驻（推荐）；② 固化 flash
  （演示更"产品化"，但迭代慢）。
