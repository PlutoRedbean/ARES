# 板级设计与验证

> 板：**盘古 200Pro+**（PG2L200H-6IFBB676）· 25 MHz · 115200 8N1 · RX **B24** / TX **C24**
> 上板步骤见 [board-bringup.md](board-bringup.md)；L2/NER 细节见 [l2-int4.md](l2-int4.md)。

## 1. 数据通路

```
UART RX ─▶ RX FIFO ─▶ l1_engine（5 个规则引擎 + 关键词 + L2 + L2b）
                            │
                            ▼  span 流
                      l1_merge（排序 / 重叠合并 / 丢弃越界）
                            │
                            ▼
                      l1_redactor（1 字节/拍，1:1 替换）
                            │
        ┌───────────────────┴──────────────────┐
        ▼                                      ▼
   TX FIFO ─▶ UART TX                   guard_report（17 字段摘要行）
```

**1:1 是硬约定**：替换器每个输入字节对应一个输出字节，60 字节前瞻、span 偏移、`--check`
的字节数全靠这一点。所以掩码也是"一个字符用同等字节数的星号"（`周杰伦` → 3 个 `*` 字节，
上位机再折成一个 `＊` 显示）。

## 2. 帧边界与串口

| 项 | 值 |
|---|---|
| 帧结束 | 收到 `LF`，或线路空闲 300000 位时间（≈2.6 s） |
| 一帧的输出 | 脱敏正文（原样字节数）+ `\r\n` + 摘要行（152 B + LF） |
| 上电行为 | **静默**：不打印 banner ✗；只有收到字节才回应 |
| LED | `led[7]` = PLL 锁定；`led[3]` = 错误（溢出/帧错，粘滞） |

### 2.1 帧长边界（已知问题）

| 帧长 | 行为 |
|---|---|
| ≤ 64 字节 | 正常：一段回显 + 一行摘要 |
| **> 64 字节** | ⚠️ 会被**提前判定结束**：摘要行插进回显中间，剩下的文本当成第二帧 |

排除了 LF 规则与 2.6 s 空闲两条路径后仍复现，根因待查（见 [../TODO.md](../TODO.md) 第 1 条）。
**当前规避**：上位机（`tools/serial_host.py` 和网页）按标点把长文本切成 ≤56 字节的帧，
逐帧发送、逐帧收、最后拼接 + 汇总审计。

## 3. 掩码策略

| 类型 | 遮法 | 例子 |
|---|---|---|
| 结构化 PII（身份证/手机/银行卡/邮箱/IPv4/车牌/USCC） | 保留**后 4 字节** | `*******8000`、`…002X` |
| 人名（type 9） | 保留**姓氏**（第一个字符），其余遮 | `周杰伦` → `周＊＊`，`欧阳娜娜` → `欧＊＊＊` |
| 地址（type 10） | **整段遮** | `深圳市光明区…5层` → 全 `＊` |
| 标点 / 空白 / 控制字符 | **永不遮** | 括号、顿号、换行原样 |

## 4. 摘要行（17 字段）

```
[guard] n=005 id18=001 id15=000 mobile=001 bank=000 email=001 ipv4=000 uscc=000
        plate=000 name=001 addr=002 kw=004 kwm=075 l2=002 l2m=006 ovf=000 mode=1
```

| 字段 | 含义 |
|---|---|
| `n` | 本帧命中的 span 总数 |
| `id18/id15/mobile/bank/email/ipv4/uscc/plate` | 各规则层计数 |
| `name/addr` | 实体层（NER）计数 |
| `kw/kwm` | 关键词命中数 / 关键词字节数 |
| `l2/l2m` | L2 语义层命中数 / 游程数 |
| `ovf` | 1 = 本帧有溢出（RX FIFO 满、TX 满、帧错），数据可能不完整 |
| `mode` | 1 = mask（固定） |

数字一律 3 位零填充；行首若不在行首会补 `\r\n`。

## 5. 资源与时序（当前位流）

| 项 | 值 |
|---|---|
| LUT | **20,879 / 159,800（13.07%）** |
| FF | 3,815 / 319,600（1.19%） |
| DRM（BRAM） | 6.0 / 415（1.45%）—— 96 KB 的 NER embedding 表 |
| APM（DSP） | 17 / 740（2.30%） |
| PLL | 1（27 MHz 晶振 → GTP_GPLL → 25 MHz 核心） |
| 时序 | WNS **+4.40 ns**、TNS 0、WHS +0.04 ns → Fmax ≈ 28.2 MHz @25 MHz |
| 位流 | `guard_board_top.sbit`（9,188,552 B） |

**25 MHz 是怎么来的**：27 MHz 一开始不收敛（WNS −38.2 ns，≈75 ns 路径）。定位到文本引擎
（邮箱/IPv4/USCC 的多字节回溯），改成**逐字节增量校验**后文本块 +22.4 ns，整板在 25 MHz
收敛。现在 25 MHz 还有 +4.4 ns 余量。

## 6. 出位流 / 烧写（PDS 2025.2-SP3）

```powershell
powershell -ExecutionPolicy Bypass -File tools\build_guard.ps1    # ~1 分钟
powershell -ExecutionPolicy Bypass -File tools\program_guard.ps1  # ~10 秒
```

- 位流是 **JTAG 灌 SRAM**，断电即丢，重新上电要再烧一次；
- 烧写用 `cdt_js`（本地 60000 端口）+ `cdt_cfg`，脚本会自动起停；
- `program_guard.tcl` 必须 **ASCII-only 且只有一个 `%s`**。

## 7. 这一轮踩过的坑（按出现顺序，都已修）

| 现象 | 根因 | 修法 |
|---|---|---|
| 板上无响应、`--check` 全红 | `tb` 用 `USE_NER=1` 默认，规则版才该用 | TB 显式传 `USE_NER=0` |
| 实体的 span 全落在出队指针之后 | NER 一窗口几十万拍，帧尾同拍 flush | 帧尾等 `busy_l2b` 落下再合并 |
| `刘德华` → 9 个星 | 掩码按**字节**给星，一个汉字 3 字节 | 上位机把整字符的星折成一个 `＊` |
| `我是马嘉祺` → 7 个星 | 模型把句尾 `LF` 并进名字（span 10 字节） | 控制字符永不算实体（RTL + 金标） |
| 括号被吃掉 | 模型把 `（` 并进名字 | 标点永不算实体 |
| `2026年` → `*026年` | 模型把 `于2` 当人名（`于` 是姓） | 名字 span 里出现 ASCII 就丢弃 |
| `楼301室` 漏遮 | 地址在数字处被模型切开，后半段没有锚点字 | 锚点表加 `镇乡村巷弄院楼室栋层幢` |
| 长帧回显中间插摘要行 | 帧被提前判结束（未定位） | 上位机按标点分帧（≤56 B/帧） |

## 8. 验收

```powershell
cd guard
python tools\serial_host.py -p COM9 --file examples\demo1_offer.txt   # 5 条段落 demo
python tools\board_smoke.py                                          # 12 句自检
```

`--check`（逐字节比金标）**只对 `USE_NER=0` 的规则版位流有效** —— 金标算不了神经网络，
NER 版会多遮，字节数自然不同。
