## 1. 目标

做一个**纯整数推理**的字符级 3 分类模型：64 字节窗口 → 每个字符 `0=none / 1=name / 2=addr`，
再把连续同类标签合成 span。要求 RTL 将来能逐位复现，所以**不许用 RNN/attention/BPE/float 推理**。

## 3. 数据（先做这个，比模型重要）

`gen_ner_data.py` 输出 JSONL，**字节偏移**：

```json
{"text": "联系人张三，手机 13800138000", "spans": [[9, 6, 1], [24, 11, 0]]}
```

`spans` 每项 `[start_byte, len_bytes, label]`，label：`1=name`、`2=addr`、`0=其它 PII`（只当负样本）。

要求：

- 姓氏表直接复用：`from host.golden.entities import SURNAMES`（64 个）；
- 名字 = 姓 + 1~2 个常见名字用字；地址 = 省/市/区 + 街道 + 门牌 + 号/栋/室（用真实地名表，含 2~3 字省市名）；
- **负样本 ≥ 40%**：订单号、金额、日期、页码、纯数字、含姓氏但不是人名的词（金额/王家村/方向）；
- **难样本 ≥ 20%**：无线索词的裸名字（`张三丰来了`）、口语地址（`那条街第三个路口东边`）、名字紧邻数字、中英混排；
- 规模：训练 ≥ 15000 句、留出 ≥ 2000 句、**难集 ≥ 1000 句（单独文件，只用于评估）**。

## 4. 模型（硬约束，为了能上板）

| 项 | 约束 |
|---|---|
| 输入 | `ids[64]` int16，UTF-8 三字节对齐切窗 |
| 词表 | ≤ 4096 项（CJK 3 字节算 1 项，ASCII 每字节 1 项），`<pad>=0`、`<unk>=1` |
| 结构 | `Embedding(→32)` + 2 层 `Conv1d(k=3, 32→32, pad=1, ReLU)` + `Conv1d(1×1, 32→3)` |
| 量化 | 权重 **INT8**（per-tensor，zp=0）；激活 INT8 非对称；累加 INT32 |
| 规模 | 参数 ≤ 60k；INT8 ≤ 120 KB；**≤ 4M MAC / 64 字节窗口** |
| 输出 | `logits[64][3]` → argmax（并列取小 id）→ 连续同类合成 span |

### 4.1 `weights_int8.npz` 键名（严格照做）

```
emb_w    int8  [vocab, 32]
conv1_w  int8  [32, 3, 32]   # [out, kernel, in]
conv1_b  int32 [32]
conv2_w  int8  [32, 3, 32]
conv2_b  int32 [32]
head_w   int8  [3, 32]
head_b   int32 [3]
```

### 4.2 推理配方（`ner.py` 必须逐行照这个写）

```
x        = emb_w[ids]                                   # int8
h1[i][o] = requant(sum_{k,ci} conv1_w[o][k][ci]*x[i+k-1][ci], mul1, zp1)
h1       = clamp(h1, 0, 127)                            # ReLU
h2[i][o] = requant(sum_{k,ci} conv2_w[o][k][ci]*h1[i+k-1][ci], mul2, zp2)
h2       = clamp(h2, 0, 127)
logit[c][i] = sum_o head_w[c][o]*h2[i][o] + head_b[c]   # int32，不重量化
label[i]    = argmax_c logit[c][i]                      # 并列取小 c
requant(acc, mul, zp) = round(acc*mul) + zp             # mul=(w_scale*a_in)/a_out
越界补 0（padding=1）；span 长度按**字节**累加
```

## 10. v1 实测结论（我这边复核过）

v1 已合入 `main`（`models/ner`，28,803 参数 / 29,004 B / 399,360 MAC）。六条门槛在
`make ner-check` 下全绿（含 numpy == ONNX 500/500）。但**在真实感文本上还不能直接当遮罩用**：

| 场景 | 结果 |
|---|---|
| 无线索词的人名（`刘德华的演唱会` / `请发给杨帆` / `存的是孙悦`） | ✅ 全部认出（规则层做不到） |
| 句中人名边界 | ❌ `王小明`→`王`、`王经理`→`王`、`陈静打了个电话`→`陈静打`、`韩梅梅是同学`→`韩梅梅是` |
| 复姓 | ❌ `欧阳娜娜`→`阳娜娜`（训练数据里没有复姓） |
| 普通文本误报 | ❌ 语料 300 句多报 **659** 个 span（`信息`/`谢。`/`g；`/`科技有`/`；`） |
| 地址 | ⚠️ 大体正确，结尾会被截（`…27号院3号` 少了 `楼502`） |
| 置信度门 | 把 `|top1-top2|` 的 int32 阈值提到 **6000**：多报 659→189，但纯靠模型仍不够 |

根因是**数据**，不是结构：

1. 负样本是"订单号/金额/日期"这类模板负样本，**缺少普通散文**（不含 PII 的中文句子）；
2. 训练集里名字几乎总是"姓+常见名"，没有**动词/副词紧跟**的例子（`陈静打了`）；
3. 没有复姓（欧阳/司马/诸葛/上官…）；
4. 地址缺"楼/室/单元"结尾的样本。

## 12. v3 要求（2026-11-19，板级实测暴露的问题）

板上跑 v2 时发现两类问题，veuillez 在 v3 修掉：

### 12.1 名字覆盖率不够

`马嘉祺的演唱会在上海` → 板上 **没遮**（`n=0`），而 `周杰伦的演唱会在上海` 遮了。
原因：训练集里的人名是从一张**很小的常用名字库**（姓 + 常见名字用字）随机拼的，
`嘉祺` 这种组合从没出现过，模型只学会了"见过的名字"。

**要求**：

| 项 | 要求 |
|---|---|
| 名字用字表 | ≥ 3000 个汉字（覆盖现代人名常用字），不能只用几十个字 |
| 全名样本 | 训练集里 **≥ 12 万个不同全名**（姓 × 名字用字随机组合即可，但要三字名占多数） |
| 真实人名 | 另加 ≥ 2000 条"真人风格"名字（可参考公开的常见姓名统计，不要抄真实个人） |
| 评估集 | 单独准备 **≥ 500 个训练时没出现过的全名**，召回 ≥ 0.95（模型没见过的名字也要认得出） |

### 12.2 地址里的数字被切开

`收件人欧阳娜娜，地址：北京市朝阳区建国路88号` → 板上遮完还剩一个 `8`：
NER 把 `建国路88号` 拆成了两段（数字附近标签翻转），中间那个字节漏了。

**要求**：

| 项 | 要求 |
|---|---|
| 地址含数字 | 训练集里 **≥ 30%** 的地址带门牌号（`X号`/`X栋X单元X室`），且标注必须**连续覆盖整个地址**，不允许在数字处断开 |
| 评估 | 新增一类"含数字地址"的评估子集（≥ 500 条），要求 **整段连续命中率 ≥ 0.98**（span 边界与标注完全一致） |

### 12.3 掩码策略变了（不影响训练，但要知道）

板上现在对**人名**保留**姓氏**（第一个字符），其余遮掉：

```
周杰伦     -> 周＊＊
欧阳娜娜   -> 欧＊＊＊      （复姓也只露第一个字）
王经理     -> 王＊＊
```

所以模型只需要把**整段人名**标出来，露哪个字由 RTL 决定。**不要**在训练时把姓氏排除在标注外。

### 12.4 v3 的验收清单（在原有 10 条之外）

| # | 门槛 |
|---|---|
| 9 | 未见过的 500 个全名：召回 ≥ 0.95 |
| 10 | 含数字地址 500 条：整段连续命中率 ≥ 0.98 |
| 11 | `马嘉祺` `周杰伦` `欧阳娜娜` `司马相如` 这类跨时代/复姓名字全部命中（写成固定测试集） |

其余（尺寸 / 整数推理 / 可复现 / 向量）保持不变。

## 13. v4 要求（2026-11-19，一封 480 字节的求职信暴露）

### 13.1 现象

拿一封真实的求职/入职信（480 字节）喂板上，模型把这些**不是 PII** 的东西标成了实体：

```
简历            -> name      ✗
公司（明远     -> addr      ✗
学历证书扫       -> name      ✗
最近三          -> addr      ✗
中国银行        -> addr      ✗
职手            -> addr      ✗
```

同时有些 span 的**起点落在 UTF-8 汉字的第 2/3 个字节上**，遮完就出现 `李�`、`流�` 这种乱码。

### 13.2 根因

v3 的训练数据是**短句**（一句话里一个人名/地址），没有"求职信 / 简历 / 邮件 / 工单"
这种**长文本**，也没有把"简历、学历、证书、公司、银行、流水"这类**看起来像实体但不是**
的词作为强负样本。

### 13.3 数据要求（v4）

| 项 | 要求 |
|---|---|
| 长文档样本 | **≥ 4000 篇**，每篇 300~1500 字节；文体覆盖：求职信、简历片段、入职/离职邮件、客服工单、合同条款、会议纪要 |
| 长文档里的正样本 | 每篇自然包含 1~4 个真实 PII（人名 / 地址 / 手机 / 邮箱 / 身份证 / 卡号），位置不限（句首、句中、括号里、破折号后） |
| **强负样本词** | 这些词**必须**出现在长文档里，且**一律标 none**：`简历` `学历` `证书` `学位` `公司` `集团` `科技` `银行` `开户行` `流水` `工资` `办理` `入职` `离职` `投递` `面试` `合同` `条款` `附件` `扫描件` `复印件` `部门` `岗位` |
| 角色词 | `联系人` `收件人` `发件人` `开户人` 这些**线索词本身**标 none（只用于上下文） |
| 字符对齐 | span 的起点和终点**必须**落在 UTF-8 字符边界（不能切在汉字中间）；生成器要断言这一点 |
| 短句数据 | 保留 v3 的全部短句样本（不能因为加了长文本而丢掉） |

### 13.4 评估（`eval.json` 新增字段）

```json
"longdoc": {"cases": 200, "span_precision": 0.0, "span_recall": 0.0, "span_f1": 0.0,
            "fp_spans_per_100B": 0.0}
```

- `cases`：**200 篇**训练时没见过的长文档（300~1500 字节）；
- `fp_spans_per_100B`：每 100 字节输出的**误报 span 数**（衡量"不乱标"）。

### 13.5 新增验收门槛

| # | 门槛 |
|---|---|
| 12 | 长文档 200 篇：span **P ≥ 0.95 / R ≥ 0.90 / F1 ≥ 0.92** |
| 13 | 长文档误报率 **≤ 0.05 span / 100 字节**（一封 500 字节的信最多 0.25 个误报） |
| 14 | 固定长信（就用这条 480 字节的求职信，见仓库 `guard/sim/doc_case.txt`）里，`简历/学历证书/中国银行/公司` **一个都不能标**，而其中的姓名/地址/手机/邮箱/身份证/卡号**必须全中** |

> 门槛 12/13/14 加上原有的 1~11，一共 14 条，`make ner-check` 要能看到。

### 13.6 注意

- 长文档训练**不要**减少短句样本：短句是主线（板子上最多的是短句），长文档是补盲区；
- 模型结构不变（64 字节窗口 / 32 通道 / INT8 / ≤60k 参数 / ≤120KB / ≤4M MAC）；
  长文档靠**滑窗**处理，不是靠更大的窗口；
- 标注工具必须断言"span 边界在字符边界上"，这一点不满足直接 fail。
