## 板级现状

- 位流：`guard/generate_bitstream/guard_board_top.sbit`
  （**20,895 LUT / 3,814 FF / 6.0 DRM / 17 APM / WNS +5.22 ns @25 MHz**）
- 实体层默认 **NER**（`USE_NER=1`）；仿真回归走规则版（`USE_NER=0`），因为金标算不了神经网络
- NER 吞吐：1 MAC/拍 ≈ 18 ms / 64 字节窗口（串口侧靠 `busy` 反压）
- 位流 JTAG 灌 SRAM，**断电即丢**，重烧 `tools/program_guard.ps1`

## 下一步（按价值排序）

1. **长帧提前收帧（最高优先）**：>64 字节的帧会被提前判结束，摘要行插进回显中间。
   已在 RTL 里排除 LF 规则与 2.6 s 空闲超时，仍复现；需要给 `guard_uart_core` 的
   `F_RUN → F_FLUSH → F_RPT` 加探针（可借用摘要行空闲位）定位第三条路径。
   临时规避：`tools/serial_host.py` 已按标点分帧（每片 ≤56 字节）。
2. **NER 并行化**：内层 32 路 MAC → 18 ms 降到 ~0.6 ms/窗口，控制逻辑不动。
3. **规则 + NER 取并集**：规则对结构化号码更严，NER 补裸名字；需要 `l1_merge` 第 7 路源。
4. **v5 数据**（Ubuntu）：真人长文语料；当前 v4 在真人写的信件上仍会误标 1~2 处
   （如 `2026年` 首位数字、`再定` 被判成实体）。任务书见 `docs/ubuntu-ner.md` §12/§13。
5. **座机号**（`0571-88888888`）暂不识别，需要新增规则 + 金标。
6. **吞吐**：3 Mbaud（需 FT232）、摘要行可关（`REPORT_EN=0`）。
7. **M3/M4**（DDR3 + 更大 MXU）：更大模型的地基，暂缓。
